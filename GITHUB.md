# Публикация VPN Atlas на GitHub

## Что подготовлено

Дизайн сайта сохранён. В `config/access-rules.json` стоит запрет страны `KG`.
Сервер проверяет IP перед выдачей HTML, стилей, скриптов, API и архива.
IP Кыргызстана и неопределённые адреса получают HTTP 403. Известные IP других
стран проходят, в том числе если это выходной адрес VPN в разрешённой стране.

`npm start` включает реальную проверку по умолчанию. На Render бесплатная .mmdb-база
скачивается автоматически без аккаунта и ключей. Инструкция: [RENDER.md](RENDER.md).
Если скачивание или открытие базы не удалось, сервер не запустится.
Это не имитация работающей защиты. `npm run demo` — отдельный локальный просмотр.

## 1. Создайте репозиторий

В своём GitHub создайте пустой репозиторий, например `vpn-atlas`.
Выберите его видимость по своему желанию. Публичный репозиторий доступен читателям
независимо от географических правил вашего сайта.

После распаковки архива откройте терминал в папке, где лежит package.json.
Для загрузки через Git (https://git-scm.com/) выполните:

```sh
git init -b main
git add .
git commit -m "Add VPN Atlas with KG access restriction"
```

Затем скопируйте HTTPS-адрес **своего** репозитория из GitHub и используйте его
вместо `YOUR_USERNAME` в следующем примере:

```sh
git remote add origin https://github.com/YOUR_USERNAME/vpn-atlas.git
git push -u origin main
```

Git может предложить обычный вход в GitHub. Не вставляйте токены в исходники,
README, команду remote или публичные сообщения.

В .gitignore уже исключены .env, закрытые .env.* файлы, .mmdb и node_modules.
Шаблоны `.env.example` и `.env.production.example` содержат только примеры и включаются.

## 2. Разверните именно Node.js-сервер

**GitHub Pages не подходит для этой проверки:** это статический хостинг.
Официальная документация:
https://docs.github.com/en/pages/getting-started-with-github-pages/what-is-github-pages

Свяжите GitHub-репозиторий со своим Node.js-хостингом или клонируйте на VPS.
Сервер должен позволять запуск Node.js, хранение/монтирование .mmdb-файла
и корректное определение IP посетителя.

Параметры запуска:

| Параметр | Значение |
| --- | --- |
| Node.js | актуальная версия 22.9+ |
| Установка | `npm ci` |
| Запуск | `npm start` |
| NODE_ENV | `production` |
| GEOBLOCK_ENABLED | `true` |
| HOST | `0.0.0.0` |
| PORT | порт, выделенный вашим хостингом |
| GEOIP_DB_PATH | путь к смонтированному .mmdb-файлу |
| TRUSTED_PROXIES | только IP/CIDR ваших обратных прокси; пусто при прямом подключении |

На Render база скачивается автоматически по RENDER.md. На другом сервере можно
выполнить `npm run geoip:download` или подключить свою базу по data/README.md.
Данные не включены в GitHub или архив. Стандартная загрузка DB-IP не требует ключа.
Если перед сервером стоит прокси, следуйте README: неверный trust proxy может
подставить адрес прокси или позволить подмену IP. HTTPS настройте на хостинге.

Не запускайте параллельно открытую статическую копию того же сайта: на ней серверные
правила не выполняются. Если ресурс должен быть ограничен, его маршруты должны
проходить через серверную проверку.

## 3. Проверьте результат

1. Публичный IP, который база относит к KG → 403.
2. Публичный IP из другой известной страны → 200.
3. Неизвестный, loopback или локальный адрес → 403.
4. Базу нельзя скачать или открыть → ошибка запуска, сайт не выдаётся без проверки.
5. `NODE_ENV=production` и `GEOBLOCK_ENABLED=false` → ошибка запуска.
6. Проверьте также прямой запрос к CSS/JS и скачиванию архива: KG должен получать 403.

`npm test` выполняет автоматические проверки на контролируемых фикстурах.
Они проверяют код и правила, но не точность вашей базы и не реальный маршрут хостинга.

Опубликованный ранее просмотр в Sites сохраняет дизайн и учебный симулятор.
Сам по себе он не является Node.js-хостингом с запретом KG.
