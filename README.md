# VPN Atlas

Русскоязычный образовательный сайт о VPN и геоблокировке.
HTML/CSS/JavaScript + **Node.js и Express**, ES Modules. Внешние платные API не нужны.

**В этой версии:** сервер запрещает IP-адреса, отнесённые GeoIP-базой к Кыргызстану
(`KG`). Известные IP других стран разрешены. Неопределённая геолокация запрещена.
Проверяется местоположение IP, не гражданство и не фактическое место жительства.
Через VPN с выходом в разрешённой стране подключение может пройти.
HTML, CSS, графика и клиентский JavaScript сохранены без изменений.

## Локальный просмотр дизайна на Windows

1. Установите актуальную версию Node.js **22.9 или новее**: https://nodejs.org/ .
2. Распакуйте архив. В Проводнике откройте папку `vpn-atlas`, введите `cmd`
   в адресной строке и нажмите Enter. Можно использовать терминал VS Code.
3. Выполните по очереди:

```sh
npm install
npm run demo
```

4. Откройте **http://localhost:3000**. Остановить сервер: Ctrl+C.

Интернет нужен для первой установки npm-зависимостей. После установки учебник
и симулятор работают локально: нет внешних запросов определения IP, аналитики
или загрузки шрифтов. Для повторяемой установки с package-lock.json можно использовать `npm ci`.

Если PowerShell запрещает запуск npm.ps1, используйте `npm.cmd install` и
`npm.cmd run demo` или откройте обычную командную строку cmd. Менять политику системы не нужно.

Демонстрационный режим привязан к `127.0.0.1` и предназначен только для просмотра
на этом компьютере. Он не выполняет реальную геоблокировку и не должен быть командой
запуска на хостинге. При NODE_ENV=production команда demo завершается с ошибкой.

## Два режима

**Локальный demo:** сайт и симулятор открываются без базы.
Переключатель VPN имитирует изменение адреса, не создаёт VPN-подключение и не
определяет реальный IP. Страны и регионы вводятся вручную.

**npm start — геоблокировка включена по умолчанию:** Express проверяет настоящий адрес HTTP-подключения
по локальной .mmdb-базе. Проверка происходит до всех страниц, API и статических
файлов. Посетители не могут изменить эти правила через симулятор или query-параметры.

Опубликованная онлайн-версия — статический учебник и симулятор.
Серверная геоблокировка работает при запуске этого Node.js-проекта на вашем сервере.
Текущая ссылка Sites показывает учебный дизайн, а не реальный запрет страны.
Публикация статической копии не активирует серверную проверку.

## Включение реальной геоблокировки

Сначала прочитайте `data/README.md`, получите City-базу и разместите .mmdb-файл.
В cmd создайте .env из примера:

```bat
copy .env.example .env
```

В PowerShell альтернативно: `Copy-Item .env.example .env`.
Измените настройки:

```dotenv
PORT=3000
HOST=0.0.0.0
GEOBLOCK_ENABLED=true
GEOIP_DB_PATH=./data/GeoLite2-City.mmdb
TRUSTED_PROXIES=
```

Если база отсутствует или повреждена, сервер завершает запуск с понятной ошибкой,
не имитируя успешную защиту. При ошибке поиска во время запроса возвращается 503.
Страна не определяется у loopback, локальных/зарезервированных адресов и
отсутствующих записей базы. Для них применяется `unknownAction`.

**Важно для локальной проверки:** при `unknownAction: "deny"` вход через localhost
и локальную сеть будет запрещён. Это ожидаемо. Сначала используйте симулятор.
Для проверки реальной базы нужен настоящий публичный адрес подключения.
Для просмотра интерфейса используйте `npm run demo`. Политика неизвестных адресов
в развёрнутом сайте остаётся deny, чтобы не разрешать неопределённые подключения.

После настройки выполните `npm start`. В production установите NODE_ENV=production
и используйте `.env.production.example` как образец переменных. При попытке отключить
геоблокировку в production сервер откажется запускаться.

## Правила доступа

Изменяйте `config/access-rules.json` и перезапускайте сервер.
По умолчанию уже задан запрет Кыргызстана:

```json
{
  "mode": "denylist",
  "countries": ["KG"],
  "regions": [],
  "unknownAction": "deny"
}
```

Ниже — альтернативные учебные примеры, они заменяют текущий запрет KG.
Разрешить **только Кыргызстан**:

```json
{
  "mode": "allowlist",
  "countries": ["KG"],
  "regions": [],
  "unknownAction": "deny"
}
```

Запретить **Германию**, остальные известные страны разрешить:

```json
{
  "mode": "denylist",
  "countries": ["DE"],
  "regions": [],
  "unknownAction": "deny"
}
```

Запретить **Берлин**, остальную Германию разрешить при известном регионе:

```json
{
  "mode": "denylist",
  "countries": [],
  "regions": ["DE-BE"],
  "unknownAction": "deny"
}
```

Правила страны и региона объединяются через ИЛИ. Совпадение целой страны имеет
приоритет: если DE есть в списке, правило действует на всю Германию. Регион в
этом списке не создаёт исключение из правила страны. Если страна определена,
но регион отсутствует, а для неё есть региональные правила — действует unknownAction.
В denylist совпадение запрещает вход; в allowlist — разрешает. Пустой allowlist
не разрешает ни одну известную страну. Неизвестные адреса всегда обрабатываются
согласно явно заданному unknownAction. Коды стран — ISO alpha-2; регионы — коды из базы.

## Обратный прокси и кеширование

При прямом подключении оставьте TRUSTED_PROXIES пустым: req.ip берётся из сокета,
а X-Forwarded-For игнорируется. За собственным Nginx на той же машине можно задать:

```dotenv
TRUSTED_PROXIES=127.0.0.1/32,::1/128
```

За другим прокси укажите только его точные адреса или минимально необходимые CIDR.
Не задавайте `true`, `0.0.0.0/0`, `::/0` или количество переходов. Доступ к origin
нужно ограничить вашим прокси, а прокси должен корректно перезаписывать заголовки.
Не доверяйте присланному посетителем IP. Проверяйте схему всей цепочки прокси.
Документация: https://expressjs.com/en/guide/behind-proxies/

Ответы при включённой проверке получают `Cache-Control: private, no-store`.
Не настраивайте CDN на игнорирование этого заголовка для защищённых маршрутов:
общий кеш не должен выдавать разрешённый ответ другому посетителю без проверки.
HTTPS и управление процессом на сервере настраиваются отдельно. Журналы IP
приложение не ведёт; проверьте отдельно логи веб-сервера, CDN и хостинга.

## Проверки

```sh
npm test
```

Тесты проверяют запрет KG по IPv4/IPv6, разрешённый выход из другой страны,
неизвестные адреса, запрет отключения проверки в production, страны, регионы, отсутствие геолокации,
смену видимой страны через условный VPN, неизвестные регионы, IPv4/IPv6,
отсутствие базы, ответы 403/503 и невозможность подмены IP через недоверенный заголовок.
HTTP-тесты используют отдельный подставной reader и явно указанный доверенный прокси;
это контролируемые фикстуры, а не проверка точности реальной GeoIP-базы.

`npm run build:static` копирует интерфейс в dist для статической публикации.
Этот вариант не запускает Express и не выполняет реальную геоблокировку.

## Границы применения

Геолокация IP приблизительна. VPN может изменить видимую страну. Это не система
выявления всех VPN и не авторизация. Для закрытых данных нужны вход и права
пользователей; для сайта только внутри собственной VPN — сетевые ограничения
и частная адресация. Программа управляет только вашим ресурсом.
